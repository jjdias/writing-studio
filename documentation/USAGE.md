# Using Writing Studio

Free, open-source, local-first. Your writing stays in a folder on your machine.

This guide describes the program as it is, Phases 1 to 5. What comes next is in [the roadmap](../roadmap/README.md).

## Start

1. `cargo run -p writing-studio-desktop`
2. **New project** — choose where the project folder goes. The app makes `Title.writingstudio` there; if you choose an empty folder whose name already ends in `.writingstudio`, the project goes in it as it is. A folder that is a project, or is inside one, is refused, so projects never end up one inside another. The status line says where the project was made.
3. **Open project** — select an existing `.writingstudio` folder.

## The project folder

A `.writingstudio` folder is the whole project, kept as plain files you can open without this program:

- Each scene is a Markdown file in `manuscript/`, named from its title when it was made (`the-harbor-3f9a.md`): its title, synopsis, status, and beats at the top, between two `---` lines, then its text. Open one in Obsidian, Typora, iA Writer, or any text editor. Characters, places, cultures, lore, timeline, and research notes are Markdown files in folders of those names.
- `project.json`, `binder.json`, `bible.json`, and `plot.json` hold the title, the binder order, the links between entries, and the plot grid. `README.md` in the folder says what each file is.
- `.local/` belongs to this computer: the search cache, snapshots, backups, writing sessions, and window layout. It is never shared, and it can be deleted; the program fills it again from the files when the project opens.
- A file edited outside the program while the project is open is not lost. Before the program writes that file, the edited version is kept beside it as `name.conflict-<time>.md`, and the status line says so. The open scene is read again when the window comes back to the front, if nothing in it is unsaved.
- A project made by a newer version says so and is not opened. A project from earlier test versions, kept in one database or with each scene as an HTML file, is refused with a message; it is not converted, and nothing in its folder is written.

[PROJECT_FORMAT.md](PROJECT_FORMAT.md) describes every file.

## Write

- Choose a scene in the binder. Type in the manuscript. It is set on a page in a reading font, about seventy characters to the line.
- The page is Markdown, shown as it reads: **bold** is bold and a heading is large, and the Markdown marks (`**`, `#`, `>`, `[text](address)`) show only where the caret is, so you can see and change them there. **Ctrl+E**, or **Settings** → **Show every Markdown mark**, shows them all (Source mode). Type the marks or use the keys: **Ctrl+B** bold, **Ctrl+I** italic, **Ctrl+U** underline, **Ctrl+Shift+X** strikethrough, **Ctrl+K** a link, **Ctrl+Alt+1** to **6** a heading, **Ctrl+Alt+0** body text. With text selected a key wraps it; inside a mark it takes it off.
- **Enter** starts a new paragraph. **Shift+Enter** breaks the line inside the paragraph. In a list or a quote, Enter starts the next item or quoted line, and Enter on an empty one ends the list or quote.
- **Settings** → **Smart quotes and dashes** turns `"` and `'` into curly quotes as you type, `--` into an em dash, and `...` into an ellipsis. **Close brackets and marks** types the closing `)`, `]`, `"`, `*`, or `_` for you. Both are off until chosen, and saved in the project.
- Text pasted from a web page or a word processor comes in as Markdown, with its bold, italic, links, headings, and lists. A web address pasted over selected text makes it a link.
- A note is written `{==text==}{>>the note<<}` and a highlight `{==text==}` (yellow) or `{==text==}{.green}`; `==text==` is a yellow highlight too. On the page a note is underlined with a mark after it that shows the note. A footnote, `word[^1]` with a line `[^1]: its text` at the end of the scene, becomes a note on the word before it. **Settings** → **Manuscript font** chooses serif or sans serif for this computer; code blocks stay in a fixed-width font. Below it, sliders set the line length (45 to 100 characters), line height, space between paragraphs, and first-line indent, and **Reset the page** puts them back. These are this computer's settings and change how the page looks while writing, not the exported file.
- Three more choices there help keep your place, and work in focus mode too. **Keep the line I type** holds the line with the caret near the top, in the middle, or near the bottom of the page while the page scrolls under it. **Fade the rest of the page** keeps the current paragraph or sentence at full strength and fades the rest. **Mark the line I am on** lays a faint band under the caret's line. All three are off until chosen, and none of them changes the text.
- While you type, the format toolbar, the bar over the page, the status bar, and the binder and Context fade out (they keep their room, so the page does not move), and they come back when you move the pointer, press a key with **Ctrl** or **Alt**, or leave the page. **Fade the bars while I type** in Settings turns this off.
- The format toolbar is one row: **Bold**, **Italic**, the paragraph style (Body, Heading 1 to 3, Code), **Quote**, **List**, **Link**, **Note**, and **More**. A button is lit when its mark is on at the caret. Clicking one leaves the caret and the selection where they were.
- **More** holds Underline, Strikethrough, Numbered list, Scene break, the highlight colors, Remove highlight, Remove link, Remove note, and Track changes.
- **Link** and **Note** ask in a small field under the selection. Enter adds it; Escape or **Cancel** leaves the text as it was. A note's field also sets what it is for: Comment, Question, Revise, or Check. The note is saved with the scene, on that text. **More** → **Remove note** takes it off; the text stays.
- **Yellow**, **Green**, **Blue**, and **Pink** in **More** highlight the selection. **Remove highlight** takes the color off. Text can carry a highlight and a note together.
- Notes, tracked changes, and spelling share the review panel under the page, one tab each. A tab shows when it has something in it. **Hide** folds the panel to its tabs, and **Beside** moves it to the side of the page. Accepting, rejecting, resolving, or removing from the panel leaves the caret where it was.
- **Navigate**, the last tab, lists the scene's headings, links, and notes in order; choose one to select it on the page.
- Notes and highlights are listed in the **Notes** tab. Click the quoted text to select it in the manuscript. In a note's row, change its kind, edit its text, **Resolve** it, or **Remove** it. A resolved note stays on the text, dimmed, and leaves the list until **Show resolved** is on. **Remove resolved** takes every resolved note off the scene. Each of these is one undo step.
- Compile writes open notes: footnotes in Markdown, bracketed text in DOCX. A kind other than Comment is named in front of the note. Resolved notes and highlights are left out of the compiled file.
- **More** → **Track changes** starts tracking the open scene from the text it has now; the toolbar says so while it is on. After that, each paragraph you rewrite, add, or remove is listed in the **Changes** tab. **Accept** keeps a change and takes it off the list. **Reject** puts that paragraph back as it was; **Ctrl+Z** undoes a reject. **Accept all** and **Reject all** do the whole list. **More** → **Stop tracking changes** keeps the text and drops the list. Tracked changes stay in the project when you close it. Only text is tracked, one scene at a time, and compile uses the text as it stands. See [Phase 4](../roadmap/done/phase-4.md).
- **Notes** in Context, under the keywords, holds what you want to remember about the scene, chapter, part, book, or folder that is chosen ("the reader should not trust Mara yet"). It is kept in that item's file and never compiled or counted.
- Changes save a few seconds after you stop typing, when you leave the field, or with **Ctrl+S**.
- **Ctrl+Z** undoes. **Ctrl+Y** or **Ctrl+Shift+Z** redoes in the document session.

## Notes

**Notes**, at the bottom of the binder, holds notes and folders of notes, as the Manuscript holds the book. A new project has two folders, yours to rename or delete: **Footnotes** and **Research**. A note is written in the page, as a scene is, and so is a folder: a folder's own text says what it is about and what is in it, and it comes first in the folder's **Copy context**, under **About**. A folder in the manuscript can have text of its own too; it is never compiled or counted. **Add a file…** in Context, for the open note, copies a file into `attachments/` and puts a link to it where the caret is. Right-click a folder of notes for **New note from template**: a template is a note to start from, with a title, keywords, and headings that say what goes under each. A new project has Character, Place, Source, and Research note; they are files in `templates/`, yours to change, delete, or add to, and right-clicking a note gives **Save as template**. A folder of notes has **Compile as footnotes** in Context: on for Footnotes, off for Research. Each note and folder is a file in `notes/`. See [Phase 14](../roadmap/todo/phase-14.md) for what notes become as the phase goes on.

## Search

The search field at the top of the binder searches the scenes' titles, statuses, keywords, and text, and the names of their chapters; the binder then shows the scenes that match and what they are in. Every word typed must be there, and the last may be unfinished: "finch des" finds a scene with "Finch" and "desert". **Ctrl+F** focuses it. `#plot` asks for scenes with the keyword plot (or one nested under it, such as `plot/subplot`), and `-#plot` leaves them out; the other words are searched as before. On the mind map, **Ctrl+F** focuses the map's filter instead.

The index is built in memory from the project when it opens, and updated when a document is saved. It is not a file in the project folder. The `.writingstudio` folder stays the source of truth.

**Escape** closes an open menu, or the binder or Context shown over the page. Otherwise it cancels a delete or restore that is waiting for its second click, or leaves focus mode when it is on, or clears the mind map's filter when that field has text, or clears the binder search, and otherwise lets go of a keyword or story entry chosen in the library.

## Organize

- The window has three columns. The **binder** on the left shows the project's name, the current book's words against its target (click it to set the targets), and the manuscript's books, parts, chapters, and folders with the scenes inside them, each scene with its status as a colored pill and its keyword colors, and each chapter with a ring that fills as its scenes reach a final status. Choose a scene to write it on the page; choose anything else to see it in **Context**, the column on the right, which holds what is said about the chosen item: never the work itself, which is on the page, the mind map, or the outline. **+ Add** in the binder adds a scene, chapter, part, book, or folder. **Ctrl+N** adds a scene and **Ctrl+Shift+N** a chapter. Under **Worldbuilding** the binder holds the story's Characters, Places, Cultures, Lore, Events, and Research, each a tree of its own: a place can hold places (Country › City › Neighbourhood › Pub), a character characters (Father › Son › Grandson). **+** beside a kind adds one at its top, **+** on a row adds one inside it; double-click or **F2** renames; drag a row before, after, or inside another of its kind; × deletes after a second click, and what it held moves up. Choosing an entry opens its page in the middle, and Context beside it says what it is (its label: "Country", "Pub", "Father", suggested from the labels its kind uses, and shown beside its name in the binder), its **Connections**, and where it is in the manuscript. A connection joins it to any other entry with a name: type how ("lives in", "son of") and to whom or what, then **Connect**; each side shows it, with × to take it away. Being inside another entry, a place's culture, lore's place and culture, and an event's place show as connections too. Plot and History are under **Views**.
- Choosing a book in the library makes it the current book: its words and target are the ones shown, and it is the one exported. Each status has its own color; Done and Final count as finished. Any other status keeps a color of its own.
- **Whole series** on the mind map and in the outliner shows every book. Pick a book there, or in the library, to make that book the one on screen, the one compiled, and the one in the status bar. The project remembers that choice. **Whole series** shows every book again and leaves compile and the status bar on the last book. Selecting a scene points compile and the status bar at that scene's book. New chapters, parts, scenes, and manuscript folders are added inside the book on screen. A scene with nothing selected goes in its last chapter. New folders go in the book on screen.
- The scene's title is the large heading at the top of the page; click it to rename the scene, and **Enter** or leaving it keeps the name. The word count is small at its right. Context (its button in the bar over the page, or **Ctrl+Alt+I**) shows the scene's **Progress** (characters, words, and reading time), then its synopsis, status, keywords, and color. The status is chosen from To do, Draft, Revise, Done, and On hold; a scene from an older project with another status keeps it as a choice. Keywords and color are for items that are not roots. Colors are None, Gold, Green, Red, Blue, and Violet. Below them, **Beats and diagnostics** and **Snapshots** fold away from their headings, and **Move to trash** sits apart at the bottom. Context is on the right in Writing, on the mind map, and in the outline.
- **Split at the caret** in Context makes a new scene, right after the open one, from the caret to the end, named after it with the next number, so "Dawn" gives "Dawn (2)" and splitting again gives "Dawn (3)", and with its status, keywords, and color. **Merge with next scene** joins the next scene in the book (in the next chapter, when this is a chapter's last scene) onto the end of the open one and moves it to the trash; its keywords join the open scene's, and its synopsis is used when the open scene has none. Notes, highlights, and tracked changes go with their text. Plot points that pointed at a joined scene point at the open one; characters and world entries linked to it are linked to the open one too; and its goal, conflict, and outcome are added to the open scene's. Each takes a snapshot of the scenes it changes first, says what it did in the status line, and is one undo step: **Ctrl+Z**, or **Undo** beside the message, puts the text, the scenes, and the links back, until another scene is opened.
- **Right-click** a binder row for what can be done to it: open it, rename it (books, parts, chapters, and folders), set a scene's status, split or merge a scene, or move it to the trash. In the trash, it offers **Restore**.
- In the binder, **Ctrl+click** picks scenes together and **Shift+click** picks every scene between the open one and the one clicked. Right-click one of them to give them all a status, merge them into the first in reading order, or move them to the trash. **Escape** lets them go.
- **Up** and **Down** move through the binder's rows, **Home** and **End** go to the ends, and **Enter** opens the row.
- **Ctrl+P** opens **Go to**: type part of the name of a scene, chapter, part, book, or folder, or of what it is in, and **Enter** opens the first found. **Up** and **Down** choose another.
- After moving an item to the trash, dragging it somewhere else, merging, or splitting, **Undo** shows beside the message in the status line while it still applies.
- **Keywords** in Context tag an item with as many words as you like. Type one and press **Enter**; × takes it off the item. A `/` nests a keyword: `plot/subplot` is under `plot`, and choosing `plot` anywhere also takes in `plot/subplot` (never the other way). A leading `#` is dropped, and a keyword with an empty part around `/` is refused, saying why. Case does not matter in any alphabet; a keyword keeps the spelling it was first given. A keyword has one color everywhere: click its dot to give it the next one. Scene cards show their keywords as dots. On the mind map and in the outliner, the keyword menu shows only the scenes that carry one, and offers a parent such as `plot` even when only its children are used.
- **Keywords** in the library, after the filters, lists every keyword as a tree, with its color and how many items outside the trash carry it or one nested under it; **By name** and **By use** order it, and a parent folds like a library row. Click a keyword to narrow the binder, the mind map, and the outliner to it; click it again, or press **Escape**, to see everything. The pencil, or **F2** on the row, renames a keyword on every item, with what is nested under it, its color, and the filters that use it; renaming it to a keyword in use merges the two after a second **Enter**, keeping that keyword's spelling and color. **Undo** beside the message puts every item's keywords back.
- **+ Filter** in the library keeps a filter as its own row: scenes with keywords (all of them, or any with **Any of them, not all**), without others (**Leave out**), linked to characters, places, or notes (**With**), with a status, or with words in their text, from every book. Choose the row to narrow the binder to them; a chapter, part, or book that has a keyword, or is linked to an entry, brings all its scenes. A filter's status is the scene's own. A filter with no name is named for what it looks for, as "flashback, not draft". The pencil opens the filter to change it, and × removes the filter, not the scenes. Keywords and filters are part of the project, so every computer that syncs it sees them.
- Labels are keywords now. A project made with labels opens with each label as a keyword on the same item. A project whose saved filters were made before filters took several keywords is refused when it opens; the message says what to change in `binder.json`.
- **In this scene** (or chapter, part, book), in Context, links the item to characters, places, cultures, lore, events, and research notes. Type a name, or pick "Mara · character" from the suggestions, and press **Enter**; click a chip to open the entry, × to unlink it. A chapter's, part's, or book's links reach every scene in it, and a scene shows those apart, dashed, as "from Chapter 1". The entry's own page lists the same links under **In the manuscript**, chapters as well as scenes. Under the chips, **Named here** offers the entries the scene's text names but is not linked to, found when the scene is opened or saved: + links one, × stops offering it for that scene until the program closes. A character is found by any capitalized word of the name; a place, culture, or lore entry by its whole name. Nothing is linked without a click.
- **Story** in the library, under Keywords, lists the linked entries by kind, each with how many scenes it reaches. Click one to narrow the binder, the mind map, and the outliner to those scenes, as a keyword does.
- **Context** lists, for a scene, every entry that reaches it, each opening the start of what it says. **Copy context** puts the scene's whole context on the clipboard as Markdown: the scene and where it sits, the scenes before and after, its plot points, and each entry with its text. It is at most 16,000 characters; when it is longer, the entries' text goes from the end of the list first, and the last line says so. Nothing is sent anywhere.
- For a chapter, a part, a book, or a folder, **Context** shows what it holds, two levels down, each with its synopsis, and every character, place, or note in it, with how many of its scenes each is in. **Copy context** gives it as Markdown: its details and notes, that outline, its plot points, and each entry with its text, so the whole book can be understood from its synopses without its text. When it is longer than 16,000 characters, the deepest synopses go first, then the others, then the entries' text, and the last line says what was left out.
- Drag a scene, chapter, part, or folder in the binder anywhere it can go, within a book or into another one. The top edge of a row or card puts the item before it, the bottom edge after it, and the middle of a library row inside it; a line or an outline shows where. A scene dropped on a library row goes into it. A chapter dropped on a scene goes beside that scene's chapter. Drop on **Trash** to discard.
- The × at the right of a binder row, shown when the pointer is over it or Tab reaches it, moves that item to the trash with what it holds. The scene that is open stays open unless it went too. **Move to trash** is also in Context. What is in the trash is under **Trash** in the binder; choose **Trash** for **Restore selected** and **Empty trash** in Context.
- Double-click a book, part, chapter, or folder in the library, or press **F2** on it, to rename it there. **Enter** or leaving the field keeps the name, **Escape** leaves it as it was, and a name cannot be empty.
- **Empty trash** asks for a second click, then deletes those items from the local database. Permanently deleting a book drops its word target. If it was the compile book, compile and the status bar move to the first book that remains.

## Mind map

**Mind map**, under **Views** in the library, shows the book in the middle and its parts, chapters, and scenes branching out to the right and the left, in binder order. With several books and **Whole series** chosen, the manuscript is in the middle. A node shows its title, its status or how many scenes it holds, and its keyword colors. Click a node to choose it: Context shows it, and a chosen scene's synopsis and word count show under the map. Double-click a scene, or press **Ctrl+Enter**, to open it on the page. The − or + at a node's edge, or **Space**, folds and unfolds its branch. The arrows move from node to node. **Tab** adds a node inside the chosen one (a chapter in a book or part, a scene in a chapter or folder) and **Enter** adds the next one beside it, of its kind; either opens its name under the map to type, and **Enter** keeps it. **F2** renames the chosen node there, and **Delete** moves it to the trash. Drag a node onto another to move it in the binder: the top or bottom edge of the node puts it before or after, the middle inside, and a line or an outline shows where; somewhere it cannot go is outlined in red. An addition and a move each offer **Undo** beside the message, as a drag in the library does.

Around the book, the map keeps what is not in it. **+ Idea** adds an idea hanging from the chosen node: under the map, type its title and a short note. An idea is never compiled or counted. **Make it a scene**, or dragging the idea onto a chapter or folder, makes it a scene there (or after the scene it hangs from), with its title, its note as the synopsis, and its lines. Dragged onto any other node, it hangs from that node instead. **Remove idea** or **Delete** takes it away. The **Story** menu shows the characters, places, cultures, lore, events, or research notes linked to what is on the map, one kind or all, each joined to what it is linked to by a dotted line; drag one onto a scene, chapter, part, or book to link it there, and double-click it to open its page. **Join** draws a line from the chosen node to the next one clicked; under the map, write a word on it ("echoes", "pays off") or × to take it away. A line is neither a move nor a link. A node dragged to an empty part of the map stays where it was put, a binder node with its branch; **Tidy** lays everything out again. Ideas, lines, and placed nodes are saved in `mindmap.json` and go with the project when it syncs.

The menu at the start of the map's bar chooses its middle: **The book**, or **Worldbuilding**. Worldbuilding shows each kind ticked beside it (Characters, Places, and so on) under the middle, with its tree as branches, and the connections between entries as lines with their names; the next menu draws all connections, none, or only those of one name, and the last centers the map on one entry, with what it is inside, what it holds, and what it is connected to around it. Click an entry to see it in Context, double-click to open its page. **Tab** adds an entry inside the chosen one (or at the top of a chosen kind), **Enter** one beside it, **F2** renames, **Delete** deletes after a second press; drag an entry onto another of its kind to nest it there, or onto its kind to bring it to the top; **Join** then another entry connects the two, and the connection is named in Context. **Fit** draws the whole map in the window; − and +, or **Ctrl** with the mouse wheel, zoom, and the map scrolls. The filter, the keyword menu, and a keyword or story entry chosen in the library dim what does not match.

## Outliner

**Outliner** is a table of chapters and scenes. Each chapter is a group row, with its title to edit, above its scenes. Click a scene's title to open it in Writing; rename a scene in Context or the binder. Edit status and synopsis in the row. The words column is that row's count. Columns take the room their content needs.

**Diagnostics**, beside **Outline** at the top, changes the table. Each scene shows its **Goal**, **Conflict**, and **Outcome**, which you type in the row, then its words, its share of dialogue, the characters from the bible it names, and the checks: a missing goal, conflict, or outcome; a scene with no text; a scene much longer or shorter than the book's usual one; no character named; long sentences. The same three fields and checks are in Context for the selected scene. The checks count what is in the text. They do not judge it. See [Phase 4](../roadmap/done/phase-4.md) for exactly what is counted.

## Recover

**History** shows the selected scene first (Snapshots, Earlier syncs, Kept from outside), then the project (Backups, Sync, Found when the project opened, Writing sessions). Each section folds from its heading.

- Context → **Snapshot this document**, or **Ctrl+Shift+S**. Restore from the list in Context or **History**.
- **Compare** on a snapshot shows, in **History**, what changed between that snapshot and the current text. Added text is marked green and removed text is struck through. **Compare with** picks a second snapshot instead of the current text. **Changed paragraphs only** hides the rest. Only text is compared, not formatting, links, or inline notes. Comparing changes nothing.
- A project made by an earlier test version, which kept everything in one database, cannot be opened by this version.
- If a project's files were changed outside the program in ways it had to repair, the status line says so when it opens and **History** lists each file and what was done. Files that came in are in **Recovered** at the top of the manuscript. A scene marked **missing** in the binder has lost its file: restore the file and open the project again.
- A file can be changed outside the program, in a text editor or by git. When you come back to the window, it is read again if you have nothing unsaved: the open scene, or the whole project when the binder, the bible, or a bible entry changed. If a save would write over a file that was changed outside, the other version is kept beside it as `….conflict-<time>.md`, and the status line says so.
- **History** → **Kept from outside** lists those kept versions. For the selected scene, **Compare** shows what differs from the current text, and **Restore** puts the kept text back, which Ctrl+Z undoes. **Delete** (second click) removes a kept file once you no longer need it.
- **Backup** writes `.local/backups/project-….sqlite` in the project folder. In **History**, **Restore this scene** puts back only the selected scene as it was in that backup; the text it replaces is kept as a pre-restore snapshot. **Restore all** replaces the whole project (second click): a safety copy is written first, and the scene files are written again from what was restored. Backups and snapshots belong to this computer; they are not part of what git shares.

## Sync

Optional. Keep a project on more than one computer through git, with any git host. **History** → **Sync** connects the project to a repository; then **Sync** in the top bar sends this computer's changes and brings in the other's. Paragraphs both computers changed are both kept, as tracked changes to accept or reject. Setting it up: [SYNC.md](SYNC.md).

Once a project is synced, **History** → **Earlier syncs** lists the selected scene as it was at each sync. **Compare** shows what changed since; **Restore** puts that text back, and Ctrl+Z undoes it.

## Compile

The three menus under the goal, in the library, are **Project** (**Save**, **Backup**, **Import Markdown files…**, and the exports), **Settings**, and **Help**, with the keyboard shortcuts and **About**. **Sync** is there too once the project is connected.

- **Project** → **Compile…** compiles a book with a profile. Choose the book and the profile, then **Compile…** and where to save. A profile says what the file is (Word, an ebook, a web page, or Markdown), its front and back matter (below), and, for Word, the font (chosen from the fonts on this computer; one named by a profile from another computer that this one lacks is listed as "not on this computer"), size, line spacing, page size, margins, indented paragraphs, and whether each chapter starts on a new page. A change to a profile is kept as it is made. A profile's **Language** (English, Português, Español, or Français) sets the number words, the words "Chapter" and "Part", the copyright line, and the matter headings; a word you changed yourself is kept when you change the language. It also says how a chapter or part is headed (its number and title, its number, its number in words, or its title, after a word such as "Chapter" that you can change for the book's language; a title that is only that word and a number, as a new chapter's is, is not repeated) and what goes between two scenes in a chapter: a scene break (* * *), an empty line, the scene's title, or nothing. The project starts with four profiles: **Manuscript** (Word, 12 point Times New Roman, double spaced, one-inch margins), **Ebook** (EPUB, with a copyright page and a table of contents), **Web page** (HTML, Georgia, with a table of contents), and **Plain text** (Markdown). A project that has profiles of its own offers a built-in one it lacks as **Add “Ebook”** in the profile list. **Copy** makes one of your own to change, **Remove** takes one away, and **Reset** puts a built-in one back as it ships; a removed built-in one can be put back from the profile list. Profiles go with the project, so every computer that syncs it compiles the same book; which profile a book uses last is remembered on this computer. In a Markdown compile, open notes are footnotes numbered across the book. A web page is one `.html` file with the text, the matter, and its stylesheet in it, and no scripts or outside files, so it opens in any browser and can go on a website as it is. It takes the font, size, line spacing, and indent from the profile, with a little more room between lines than a page has; the contents link to each chapter; open notes are numbered and listed at the end, each linked to its place and back; highlights are left out. Printed from a browser, each chapter starts a new page. An ebook is an EPUB 3 file that ebook readers and apps open: each part, chapter, and page of matter is a page of its own, the reader's table of contents lists the parts and chapters, and open notes are listed at the end and linked both ways. Its title, author, language, and date are in the file, with an id that stays the same each time the book is compiled, so a reader knows a new compile is the same book. **Cover**, in the dialog when the profile makes an ebook, takes a PNG or JPEG picture of up to 20 MB and keeps it with the project for that book; the picture is checked by what is in it, not by its name. The reader chooses the colors, and can change the type.
- **Preview** in the Compile dialog shows the book as the profile sets it, in the window, before anything is written: the web page compile with the profile's type, matter, headings, and scene breaks, from the text as it is now. For a Word or ebook profile it shows the text and matter, not the pages. **Back** returns to the profile; **Compile…** goes on from there.
- **Compile…** looks over the book first. When it finds something that may not be meant to go out, the dialog lists it by kind: items left out of the compile, scenes with no words, parts, chapters, or scenes with no title where the profile prints one, open notes, tracked changes not yet accepted or rejected, and unknown words when spellcheck is on. Click a line to open that item; **Back** returns to the profile; **Compile anyway…** compiles as it is. Nothing in the list stops a compile, and with nothing to show it goes straight on. Afterwards the status line names the file and the profile, how many chapters and words went in, and what the check found.
- **Include in compile**, in Context and in the right-click menu, leaves a book, part, chapter, or scene out of compile, with what it holds. It stays in the binder and the outliner, dimmed. Chapters and parts are numbered among those compiled.
- **Front and back matter**, in each profile: a **Title page** (the book's title, its **Subtitle**, and the **Author**), a **Copyright page** (one line you edit; `{year}` and `{author}` are filled in), a **Dedication**, and **Contents** (the parts and chapters that are compiled) go before the text; **About the author** and **Also by** (one title to a line) go after it. Tick a page to put it in and its text box opens below. A page with no text is left out, and its text is kept while it is off. In Word each page of matter starts a page of its own. The subtitle belongs to the book and the author to the project; both are set at the top of the dialog and go with the project when it syncs. Matter is not a scene: it is not in the library and counts toward no target. Its headings follow the profile's **Language**, and each can be changed in its own box; "{author}" in the "Also by" heading is filled in.
- **Project** → **Markdown folder…** writes the whole project as a folder of Markdown files: every scene in reading order, the bible, and a `README.md` that lists them. Use it to read the book anywhere, or to take it to another writing program. Each item's keywords are its `tags:`, as Obsidian reads them, with a space written `-`.
- **Project** → **Import Markdown files…** brings Markdown files in as new scenes, where a new scene would go. A title in the file's front matter is used; otherwise the file's name. Its `tags:` or `keywords:` become the scene's keywords.
- The current book is the one exported: choose it in the library, or open one of its scenes. Other books stay out of the file. The title page uses that book's title and subtitle.
- Research and trash are not included.

## Targets

The status bar shows the current book's words and target first, then in Writing the open scene, then words added today, this sitting, and the save state. A count that does not fit in a narrow window is left out. The book's total matches the outliner for the book chosen for compile: each scene, and a chapter only when that chapter has no scenes. Research notes are not included. Today and the sitting use that book's own baselines, so another book's count does not change them. The daily target is still one number for the project. Click the goal under the project's name in the library to set both targets; they are saved in the project. **Finish by** there gives the book a deadline: the library shows the date and the time left under the goal, and the status bar says how many words a day meet it, counting today. **Clear** takes the deadline off. The deadline is part of the book, so every computer that syncs the project sees it. **History** lists completed sittings. A sitting is stored the next time you open the project, when any book added words. Today's count for each book starts again on the next local day.

## Modes

Writing, Mind map, Outliner, Plot, Characters, World, Research, History. **Ctrl+1** to **Ctrl+8** open them in that order. **Mind map** and **Outline** are under **Views** in the library, after the books, and the page opens when a scene is chosen; an entry's page opens from Worldbuilding. The middle of the window shows the page, the mind map, or the outline. A mode with nothing in it says what goes there and has the button that adds the first one. Choosing the mode that is open does nothing. The bar over the page also has **Focus**, which hides everything but the page and a word count (**Escape** leaves it), and the Context button.

## Plot

**Plot** lists the plotlines beside the one that is open. Add a plotline, then add plot points along that line. Each point has a title, a short summary, and an optional link to a manuscript scene. The list of scenes is labeled book / chapter / scene, so the same chapter in two books stays distinct. **Open** jumps to that scene. **Earlier** and **Later** change the order on the line. Deleting a plotline asks for a second click and removes its points. The grid is saved in the project folder. Emptying trash drops links to scenes that were permanently deleted.

## Characters

**Characters** keeps a local cast. Each profile has a name, a role, and a longer description. Motivations are a list on that character. A relationship names another character and how they are connected. Deleting a character asks for a second click and also removes their motivations and relationships. The cast is saved in the project folder. Each profile can link manuscript scenes, or chapters, parts, and books for every scene in them, under **In the manuscript**. Emptying trash drops those links.

## World

**World** keeps locations, cultures, lore, and a timeline in the project. A location can name a culture. A lore entry can name a location and a culture. A timeline event has a when-label, a title, what happened, and an optional location. **Earlier** and **Later** change event order. Deleting an entry asks for a second click and clears links that pointed at it. Each entry can also link manuscript scenes, or chapters, parts, and books, under **In the manuscript**. Emptying trash drops those links.

## Research

**Research** is the only editor for research notes and their files. Each note has a title, notes, and files. **Attach file** copies the file into `attachments/` inside the project folder. **Open** launches it with the usual app for that file type. Removing a file or a note asks for a second click and deletes the copy in `attachments/`. A sqlite backup does not include those files; copy the whole project folder to keep them. A new project seeds one binder research note. Opening a project copies notes that still sit under the binder Research section into this library, then removes those notes and research folders from the binder. Characters, world notes, plot, and the manuscript stay where they are. A note can link manuscript scenes, or chapters, parts, and books, under **In the manuscript**. Emptying trash drops those links.

## Layout

The arrangement is saved in the project. The binder is on the left and Context on the right; drag the edge of either beside the page to resize it. The binder width stays between 180 and 480 pixels, and Context's between 220 and 560. Double-click that edge to reset the width.

The binder button at the left of the bar over the page, or **Ctrl+Alt+B**, shows or hides the binder. The Context button at its right, or **Ctrl+Alt+I**, shows or hides Context. **Ctrl+B** still bolds the selection in the manuscript.

In a narrow window Context folds away first, then the binder, so the page keeps its room: with the default widths, below about 960 and 660 pixels wide. A folded panel comes back over the page from its button; a click beside it or **Escape** closes it. The window is never smaller than 720 × 520.

## Spelling

- Words that are not in the dictionary are underlined in red in the manuscript and listed in the review panel's **Spelling** tab. The word you are still typing is not underlined until the caret leaves it.
- Click a word in the list to select it in the manuscript and see suggestions. A suggestion replaces **every** copy of that word in the open scene, as one undo step. **Find next** moves to the next copy. **Add to project dictionary** accepts the word everywhere in this project.
- **Project dictionary** lists the accepted words. Click one to take it out.
- Words in character, place, and culture names are accepted without adding them. Numbers, single letters, and words in capitals are not checked.
- **Settings** → **Spelling**, at the top of the library, chooses the dictionary or turns spellcheck off. English (US) is built in. For another language, put its Hunspell files (`name.aff` and `name.dic`) in a `dictionaries` folder inside the project folder and reopen the project. Dictionaries installed on the computer in the usual Hunspell folders are listed too.
- Spellcheck runs on this computer. No text leaves it.

## Themes

**Settings** → **Theme**, at the top of the library, saves **Dark**, **Light**, or **Paper** in the project. Dark matches VS Code Dark+. Light matches VS Code Light+. Paper keeps the warm chrome and sets the manuscript on a cream page.
